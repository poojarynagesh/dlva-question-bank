## Workflow: new lecture notes arrive

When a new `Notes_… .md` file is pasted into `DLVA_Notes` (or into the chat):

1. **Read the notes in full.** Pick out definitions, equations, worked numbers, the professor's examples and the in-class Q&A — the Q&A shows what the professor thinks is subtle.
2. **Write the bank** `assets/qb/Lnn.js` (next free number) in the format below. Target: 8–10 MCQs (1–2 marks, mostly multi-correct), 4–5 short questions (2 marks), 1 long question (8 marks, 4–6 parts) when the topic supports one.
3. **Register the lecture**: add a row to `LECTURES` in `tools/make_pages.py` — `(id, "D Mon 2026", nav title, full title, one-sentence lead, "post")`.
4. **Generate and index**: `python tools/make_pages.py` then `python tools/build_index.py`.
5. **Check**: open `lectures/Lnn.html`; every question renders, no red KaTeX errors, MCQ marking works, model answers reveal. The mock-paper generator picks the new bank up automatically.
6. **Log it** in the table above, commit, and `git push` — GitHub Pages republishes within a minute or two.

## Question quality bar (from the real paper)

Questions must test reasoning at the level of the midterm, not recall. Each carries a tag `k`:

- **scenario** — a situation to diagnose ("high training error — what helps?").
- **trap** — plausible statements, some subtly false ("tanh doesn't vanish", "deeper layers learn slower").
- **compute** — a one-step number that proves you know the formula (1×1 filter on 16 channels = 17).
- **interpret** — explain why / what will happen (ReLU→sigmoid always ≥ 0.5; exposure bias).
- **design** — build something (choose weights), then analyse it (fixed points, gradients).

Rules:

- Every MCQ explanation (`x`) says why each wrong option is wrong.
- Numbers in questions are worked through and checked.
- Do not copy real exam questions into lecture banks; write variants. The real paper lives only in `assets/qb/sample.js`.
- Ground questions in the lecture's own examples; add standard knowledge where it sharpens a question.

## Bank format

```js
(function () {
  const R = String.raw;            // so LaTeX backslashes survive; never write `${` inside
  (window.QB_ALL = window.QB_ALL || {})["L20"] = {
    id: "L20",
    points: [R`revision bullet with $math$`, ...],
    mcq:   [{ pts: 1, k: "trap", single: true /* omit for multi-correct */, q: R`...`, o: [R`a`, R`b`, R`c`, R`d`], a: [0, 2], x: R`why` }],
    short: [{ pts: 2, k: "interpret", q: R`...`, a: R`<p>model answer</p>` }],
    long:  [{ pts: 8, k: "design", q: R`<p>setup</p>`, parts: [{ pts: 2, q: R`...`, a: R`<p>...</p>` }] }],
  };
})();
```

Optional on a long question: `roman: true` for (i)(ii)… labels, or `labels: [...]` for custom ones. Use `\lt`/`&lt;` rather than a bare `<` inside maths, and avoid a plain `$` for currency.
